# G4 Auto-WiFi attachment smoke, 2026-09-29

The opt-in headless Auto-WiFi attachment cross-built for the G4 and passed a
TCP rendezvous page transfer. Multicast beacon transmission was observed.
**Native DNS-SD service publication/resolution and automatic peer discovery are
not yet qualified.** This is the existing shared vendor bridge, not a separate
2.4 GHz AP/client deployment.

Build with the named `build.hopspot.g4` task, the qualified toolchain and Zig,

## Reproduction and observations

Upload the application to a fresh private directory under `/tmp`, verify its
hash, then run on the explicitly chosen lab bridge:

```sh
./personal-hopspot-headless --state-dir ./state --listen 192.168.12.1:4345 \
  --auto-wifi-device br-ahwlan --run-for 40
```

Use the reported node-page destination with the existing `fetch_page` probe on
another machine, targeting **192.168.12.1:42699**, the Auto-WiFi rendezvous port,
rather than the explicitly supplied ordinary TCP listener at 4345.

Observed: `hopspot_page_verified bytes=3542 rtt=RttMillis(52)`.
The probe establishes a Reticulum link and compares the entire encoded shared
Hopspot page. This is a manually targeted rendezvous transfer, not automatic
DNS-SD discovery. One pre-transfer sample showed RSS 5,080 KiB and high-water
5,192 KiB; these are not sustained-load memory bounds.

A separate bounded eight-second run captured seven seconds on `br-ahwlan`:

- Four 32-byte IPv6 Reticulum discovery beacons on UDP 29716, spaced about 1.6 s.
- IPv4 mDNS PTR queries for `_reticulum._tcp.local.` and `_reticulum._udp.local.`.
- Eight captured packets, zero kernel drops.
- No service announcement/resolution demonstrated by this sample. A separate
  bounded native browse produced no retained output, so it is inconclusive.

The board lacks the `timeout` command. The successful capture used a background
`tcpdump`, a shell timer and SIGINT, while the application had its own `--run-for`
deadline. Discovery queries alone do not establish that publishing works.

All temporary hosts stopped with persistence flushes and `hopspot_stopped`.
The initial cleanup showed ports 4345/42699 and the test UDP sockets gone while
existing services remained. Subsequent bounded runs also exited gracefully.
No pending UCI changes were reported. No browser assets, network migration,
service installation, or radio reconfiguration was performed.

## Host checks

On macOS, all-feature headless tests passed: two new option-policy tests, the
existing HaLoW option test, two host unit tests, controlled two-hop page transfer,
two lifecycle tests, and WebSocket page/capacity recovery. Clippy passed for all
features and targets with warnings denied. The Linux qualification entrypoint
now includes `wifi-auto`; that Linux suite was not executed on this Mac.

Commands used the headless manifest with `cargo test --offline --locked
--features wifi-auto,websocket,wifi-halow` and `cargo clippy --offline --locked
--all-features --all-targets -- -D warnings`. Local debug symbols/incremental
output were disabled after disk pressure; socket tests ran with local networking
permitted. Validation registry verification and `git diff --check` passed.
