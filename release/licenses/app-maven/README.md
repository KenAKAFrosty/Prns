# Application Maven declaration evidence

The authoritative component membership is `applications/tools/native-bindings/android-maven-baseline.json`, resolved separately for `debugRuntimeClasspath` and `releaseRuntimeClasspath`. The current counts and coordinates are recorded in the baseline and resolution report. The qualification recipe also records project components and exact external artifact hashes. Release metadata resolution is not compiled, signed or device-tested release acceptance.

`pom-license-evidence.json` preserves each selected POM and the parent documents needed to interpret its declarations. `pom-sources/` contains their exact bytes. Validation binds content hashes, actual/inherited coordinates, parent coordinates, and license declarations to the checked baseline. Expo POMs additionally identify the exact npm archive and integrity that supplied the local Maven repository. The baseline binds the selected package manifests and lockfile by SHA-256. The Expo 58 native modules obtain their POMs from the locked npm packages; other selected Android components come from the Gradle resolution. A Gradle cache observation does not establish remote repository provenance.

This is declaration evidence, not license-policy approval or a complete artifact-attribution review. Coordinates declaring ML Kit Terms of Service or Android Software Development Kit License must not be relabeled Apache-2.0; the report lists the exact selected coordinates. JNA declares alternatives; no new selection is inferred here. Existing permissive terms reproduced elsewhere do not substitute for reviewing package attribution and applicable terms.

After the evidence checks pass, the report labels this hold **manual release-policy review pending** and lists the coordinates declaring these terms, including JNA’s declared LGPL alternative. This list neither classifies every license nor selects an alternative. The manual hold covers the complete selected Maven closure and remains separate from computed integrity, origin, attribution and dependency mismatches, which fail evidence verification directly. The application release audit remains failed until the manual review is resolved; no exception or approval is inferred from passing evidence checks.

`pom-origins.json` binds all non-Expo POMs (including parent documents) to byte-identical files fetched from Google Maven or Maven Central. The Expo POMs retain their exact npm archive custody. This verifies POM origin; it does not prove origin of every binary artifact.

`resolved-runtime.json` preserves the actual debug/release resolution report. `artifact-notices.json` binds all resolved artifact variants to that report's SHA-256 values and selected configurations. The artifacts were read from the existing Gradle cache or integrity-checked Expo npm archives, and every artifact matched its recorded SHA-256. Available notice files, including notices inside `classes.jar`, are preserved under `artifact-notice-sources/`. Larger text blobs use deterministic gzip to avoid repeating megabytes of license text in source control; both compressed and original bytes are checked. Git preserves these evidence bytes without line-ending conversion.

The report parses Google's packaged `third_party_licenses.json` byte ranges against the corresponding exact text, rejects duplicate, overlapping, malformed or out-of-bounds ranges, and emits the attributed texts through the ordinary notice generator. Names in that index are attribution labels, not inferred SPDX licenses. Repeated license texts are deduplicated in the generated notice bundle; other packaged license files are also retained. The actual JNA archive explicitly declares `Apache-2.0 OR LGPL-2.1-or-later`, which establishes the alternatives without inferring them from two POM elements.

This evidence does not claim that every archive supplies all required attribution, that nested native binaries received a complete source audit, or that the Google terms or otherwise unapproved licenses were accepted. No policy row or advisory is waived. Generation remains separate from the failing application release-review gate.
